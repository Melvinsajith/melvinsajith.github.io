How I build robot systems

From sensor data to safe motion: a typical ROS 2 navigation stack, with the components and interfaces I work on.

01 / SensingLiDAR + odometry

Laser scans, IMU data and wheel feedback enter the ROS 2 graph.

02 / StateTF2 + localization

Coordinate frames and pose estimation connect the robot to its map.

03 / MappingSLAM Toolbox

Generate an occupancy map from sensor observations.

04 / PlanningNav2

Plan routes, handle obstacles and execute waypoint goals.

05 / Controlcmd_vel + feedback

Command the mobile base and monitor robot state.

Illustrative system architecture, not a claim that every project uses the identical pipeline.

DIO Robot Connect

An Android control and monitoring interface for ROS 2 mobile robots using rosbridge_server. View sensors, teleoperate a compatible robot and send navigation goals from a phone.

How it works

The app talks to the robot over WebSockets through rosbridge_server, subscribing to ROS 2 topics and calling services in both directions. Topic names are configurable, so the same app works across different robots.

Key features

  • Real-time LiDAR visualization
  • Live camera streaming
  • Robot pose and global map view
  • Nav2 goal poses and waypoint routes with live feedback
  • Dead-man control and emergency stop

  • WebSockets

Autonomous restaurant service robot

A modular mobile robot that maps a restaurant on its own and delivers orders to tables, built and tested end to end in simulation.

How it works

SLAM Toolbox builds the map of the dining room. Nav2 then localizes the robot on that map and plans paths to predefined delivery points, all running as modular ROS 2 Humble packages in Gazebo Classic 11.

Key features

  • Indoor mapping and localization
  • Path planning to table delivery points
  • Python Tkinter panel for waypoints, teleoperation and diagnostics
  • ROS 2 Humble
  • Gazebo Classic 11
  • Nav2
  • SLAM Toolbox
  • Python
  • Tkinter
Simulation results. Previously reported for a 10 × 10 m Gazebo restaurant world: 95% successful navigation in obstacle-free trials; 85% with dynamic obstacles; approximately 30 s average delivery time per table.
